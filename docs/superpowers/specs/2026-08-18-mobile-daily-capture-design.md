# 移动端每日记录与模板设计

## 目标

把每日笔记从“适合阅读但不易输入”的折叠 Callout，改为电脑和 iPhone 都能直接编辑的普通 Markdown 标题；用一个 iOS“记录今日”快捷指令唤起 Obsidian，由 HZ 工作台插件可靠地创建今日日记、写入指定栏目、管理照片、计时和收支。资源库继续通过 Remotely Save 同步。

## 已确认的使用方式

- iPhone 是主要移动记录设备，允许快捷指令短暂打开 Obsidian。
- 只保留一个“记录今日”快捷指令菜单。
- 今日照片从相册选择；每天展示一张，再次选择时替换；不填写说明。
- 照片自动转为最长边 2048px、JPEG 85%，默认保存到 `06 附件/日记照片/<年份>/<YYYY-MM-DD>.jpg`。
- 柳比歇夫时间记录支持自动开始/结束和手动补录。记录字段为开始、结束、类别、事项和可选关联项目。
- 开始新事项时自动结束上一项。跨午夜自动拆到两天。
- 默认时间类别：`工作、学习、沟通、生活、运动、通勤、休息、娱乐、其他`；设置中可调整。
- 时间汇总显示当天总时长和各类别小计。
- 随手记支持键盘输入或语音听写，写成 `- HH:mm 内容`，不强制分类或双链。
- 今日摘要和重要决定与分流在晚间手动填写，插件不介入。
- 今日任务与明日行动继续通过 `hz-tasks` 只读展示；所有任务修改仍在 TickTick 中完成。
- 今日收支保留并支持快捷录入。字段为收入/支出、分类、事项、金额和可选关联项目；日期时间自动填写。
- 默认支出分类：`餐饮、交通、购物、居住、医疗、娱乐、学习、项目、其他`。
- 默认收入分类：`工资、设计费、报销、奖金、其他`。
- 收支汇总显示今日收入、今日支出和净额，默认人民币。
- 旧日记不批量迁移。新版结构只用于后续创建的日记。

## 模板结构

模板保留 frontmatter、日记标题和现有 Templater 导航脚本，正文改为普通标题，顺序固定为：

1. `## 今日照片`
2. `## 柳比歇夫时间记录`
   - `### 时间流水`
   - `### 时间汇总`
3. `## 随手记`
4. `## 今日收支`
   - `### 收支流水`
   - `### 收支汇总`
5. `## 今日整理`
   - `### 今日摘要`
   - `### 重要决定与分流`
   - `### 今日任务`
   - `### 明日行动`

插件管理区域使用阅读模式不可见的成对 HTML 注释：

- `hz:daily-photo`
- `hz:time-entries`
- `hz:time-summary`
- `hz:quick-notes`
- `hz:finance-entries`
- `hz:finance-summary`

插件只修改对应边界内部，边界外的手写内容逐字保留。标题或边界缺失时停止写入并提示，不猜测插入位置。

## 插件架构

### 纯逻辑层

`daily-capture-model.js` 负责：

- 定位与替换受控块，保持原换行格式；
- 格式化、解析并追加随手记、时间和收支记录；
- 按本地午夜拆分时间区间；
- 计算总时长、类别小计、收入、支出和净额；
- 生成固定照片路径；
- 验证类别、时间、金额和项目链接文本。

该层不依赖 Obsidian，可用 Node 测试完整覆盖。

### Vault 服务层

`daily-capture-service.js` 负责：

- 在日记目录按 frontmatter/文件名日期查找日记；
- 对今天缺失的日记调用 Obsidian Daily Notes 命令创建，并等待 Templater 完成；
- 开始计时时先确保当天日记存在；
- 完成计时时按日期更新一个或两个日记；
- 通过一次 `vault.modify` 写入每篇 Markdown；
- 通过 `adapter.writeBinary` 写入或替换固定 JPEG；
- 发生错误时不提交半截 Markdown。

### 移动交互层

`daily-capture-modal.js` 负责照片、开始计时、手动补录和收支的触控友好表单。iOS 快捷指令通过 `obsidian://hz-workbench-capture` 协议传入动作；随手记可把快捷指令的键盘或听写结果作为短文本传入。插件另提供同名命令，便于桌面端验证和使用。

活动计时状态保存在 HZ 插件数据中：`activeTimer = { startedAt, category, title, project }`。正式记录始终以日记 Markdown 为准。开始新事项时，服务先结束并写入旧事项，再保存新状态。

## 设置

插件版本提升为 `0.3.0`，新增：

- `dailyPhotoFolder`，默认 `06 附件/日记照片`
- `dailyPhotoMaxEdge`，默认 `2048`
- `dailyPhotoQuality`，默认 `0.85`
- `timeCategories`
- `expenseCategories`
- `incomeCategories`
- `currencySymbol`，默认 `¥`
- `openDailyAfterCapture`，默认关闭
- `activeTimer`，默认 `null`

列表设置使用英文逗号或中文逗号分隔，保存时规范化并去重。

## iOS 快捷指令

“记录今日”显示：今日照片、开始事项、结束事项、手动补录时间、随手记、今日收支、打开今日日记。快捷指令不直接访问 Remotely Save 的本地文件；它只调用 HZ 协议。照片由插件打开 iOS 相册选择器。随手记分支允许键盘输入或“听写文本”。

Windows 端无法生成并签名可直接安装的 Apple 快捷指令，因此发布包同时提供一份逐步配置文档和每个动作的 URI 示例。

## 错误与安全

- 创建日记失败、模板未完成、标题/边界缺失、图片解码失败、时间无效或金额无效时显示中文 Notice。
- 对 Markdown 先计算完整候选文本，再调用一次修改；不做多次部分写入。
- 跨午夜更新两篇日记时，先完成两篇候选文本验证，再顺序提交；第二篇创建失败时第一篇不修改。
- 写照片前先完成压缩；Markdown 更新失败时不删除旧链接。
- 不修改历史日记、TickTickSync、布局文件或既有任务数据。
- live 修改前完整备份模板和 HZ 插件并核对 SHA-256。

## 验收

- 模板标题、顺序、标记和任务代码块完全匹配规格。
- Node 测试覆盖受控块、手写内容保留、时间拆分/汇总、计时替换、收支汇总、照片路径和所有错误边界。
- 生产边界测试确认协议注册、命令、设置和只读 TickTick 路径不回退。
- 完整测试、语法检查、构建和发布包一致性全部通过。
- live 安装只覆盖 HZ 插件发布文件；模板从已校验备份修改。
- Windows Obsidian 验证新模板可创建、各动作可写入测试副本；不创建或修改真实日记内容作为测试数据。
- iPhone 端按配置文档完成快捷指令后，再进行相册、听写、计时、收支和 Remotely Save 双端验收。
