# 月复盘自动创建与清晰展示设计

日期：2026-08-21  
状态：已完成讨论，待用户审阅书面规格  
项目：HZ 个人工作台 Obsidian 插件

## 目标

本设计同时解决三个问题：

1. 当前月创建第一篇合法日记时，自动生成排在该月最前面的月复盘文件。
2. 本月任务只展示真正计划在本月的 TickTick 任务，不再混入仅于本月创建的无日期任务。
3. 本月任务和本月收支改为层级清楚、电脑与 iPhone 都易读的展示方式。

所有 TickTick 数据保持严格只读。自动创建不依赖 Templater 或当前编辑器焦点。

## 非目标

- 不自动补建历史月份月复盘。
- 不重命名已有旧月复盘。
- 不修改任何日记正文。
- 不调用 Templater 命令或依赖活动标签页。
- 不创建、修改、完成、删除 TickTick 任务，也不主动触发 TickTickSync。
- 不在本功能中改变每日模板、每日记录 marker 或工作台自由布局。

## 一、自动创建本月复盘

### 文件位置与命名

假设 `dailyFolder` 为 `01 日记`，2026 年 8 月自动创建：

`01 日记/2026年/8月/2026年-08-00-月复盘.md`

`00` 使月复盘在默认文件名排序下稳定排在每日文件之前。

下列任一文件存在时，都视为该月已有月复盘：

- 新名称：`YYYY年-MM-00-月复盘.md`
- 旧名称：`YYYY年-MM月复盘.md`

插件不重命名旧文件，不重复创建，也不覆盖已有文件。

### 合法日记判定

触发源必须同时满足：

1. 位于 `${dailyFolder}/${year}年/${M}月/`。
2. 扩展名为 `.md`。
3. basename 严格符合 `YYYY年-MM-DD-星期X`。
4. 文件名年月等于电脑当前年月。

当月目录中的项目笔记、临时笔记、月复盘或命名错误文件不触发。

### 两条触发入口

#### Vault 就绪后的启动检查

插件启动并等到 Vault 可用后，只检查电脑当前月份：

1. 定位当前年月目录。
2. 查找至少一篇合法日记。
3. 检查新旧两种月复盘名称。
4. 有日记且没有月复盘时创建新名称文件。

没有当月日记时不创建，也不扫描历史月份。

#### Vault create 事件

监听新文件事件。只有新文件通过合法日记判定时才调用月复盘保障器，其他文件立即返回。

### 幂等与并发

启动检查和新文件事件可能同时发生。保障器必须：

1. 对当前月份共享一次进行中的创建 Promise 或等价锁。
2. 进入创建前检查新旧两种文件。
3. 真正写入前再次检查目标文件。
4. 同名文件已经出现时视为成功，不覆盖。
5. 成功或失败后都释放锁。

同一月份最多创建一份月复盘。

### 生成正文

插件直接复用月复盘正文渲染模型，生成最终 Markdown，包括：

- frontmatter：`type: 月复盘`、`month: YYYY-MM`、`tags: 月复盘`
- 标题：`# YYYY年MM月复盘`
- 本月任务：`hz-month-tasks`
- 本月收支：`hz-month-finance`
- 本月总结四个栏目

生产代码只保留一个月复盘正文来源。自动创建和手动 Templater artifact 都从该来源生成，避免内容漂移。

### 新旧名称兼容

月份解析器同时接受：

- `YYYY年-MM-00-月复盘`
- `YYYY年-MM月复盘`

两种名称解析为相同的 `YYYY-MM`。若 frontmatter `month` 与文件名月份不一致，继续显示明确错误。

手动模板 `F:\Obsidian\07 模板\月复盘模板.md` 优先提示新名称，同时兼容旧名称。工作台轮播在读取 frontmatter 或正文前排除所有月复盘文件。

### 用户体验与错误处理

创建成功后：

- 保留当前日记和当前标签页。
- 不自动打开月复盘。
- 只显示一次中文 Notice：`已自动创建 YYYY年MM月复盘`。

创建失败时：

- 不修改触发日记。
- 不留下半成品。
- 记录一次 `[HZ Workbench]` 错误日志。
- 显示一次中文失败提示，引导稍后手动创建。
- 不循环重试；下次插件启动或下一篇合法日记创建时重新检查。

## 二、本月任务的数据规则

### 当前问题根因

现有 `taskMonthDate()` 使用“计划日期，否则任务创建日期”。因此本月新建但没有安排在本月的收件箱任务、未来任务和零散任务会被归入本月，造成数量虚高和内容混乱。

### 新筛选口径

- 只使用规范化任务的计划日期或截止日期。
- 日期属于目标月时才进入月复盘。
- 没有计划日期和截止日期的任务不展示。
- 不再使用任务创建日期决定月份。
- 已完成和未完成任务都展示。
- 排序顺序：日期、定时时间、全天任务、标题、稳定原始顺序。
- 任务来源仍是 TickTickSync 只读 repository 的单次快照。

## 三、本月任务的日期时间轴

### 顶部指标

显示四个紧凑指标：

- 任务总数
- 已完成
- 未完成
- 完成率

### 本地筛选

提供三个原生按钮：

- 全部
- 已完成
- 未完成

筛选只改变当前 processor DOM，不写 TickTick、不写日记、不持久化。每次重新渲染默认回到“全部”。

### 日期分组

- 只渲染有任务的日期。
- 日期标题显示中文日期、星期和当天完成进度。
- 每条任务只保留时间、标题和状态标记。
- 已完成任务使用完成符号与低强调文字。
- 未完成任务保持正常文字，不使用刺眼警告色。
- 全天任务使用“全天”标签并排在当天定时任务之后。
- 无任务时显示简短空状态。

### 响应式

- 桌面端使用紧凑日期时间轴。
- 小于等于 700px 时变为单列，时间、标题和状态保持清楚。
- 不允许横向滚动。
- 操作目标满足移动端触控尺寸和键盘 `focus-visible`。

## 四、本月收支的分层展示

### 顶部指标

显示：

- 本月收入
- 本月支出
- 本月结余

### 支出分类排行

- 只统计有效支出记录。
- 按金额从高到低排列。
- 默认展示前 5 个分类。
- 其余分类合并为“其他”。
- 每项显示分类名、金额、占本月总支出的百分比。
- 用简洁横向比例条表达占比，不使用复杂饼图。
- 没有支出时显示简短空状态，不渲染空排行。
- 比例条必须同时保留文字和数值，不能只依靠颜色传达信息。

### 可展开明细

全部流水默认收起，只显示：`查看全部明细（N 笔）`。

展开后：

- 按日期分组。
- 每条显示时间、事项、分类和金额。
- 收入、支出用符号和轻量颜色区分，同时保留文字语义。
- 再次点击可收起。
- 展开状态只属于当前 DOM，不写设置和日记。

无有效流水时，不显示展开按钮，只显示“本月暂无收支记录”。

### 错误信息

- 无法解析的收支和读取失败放在明细区底部的独立提示区。
- 错误来源按钮可以在新标签页打开对应日记。
- 正常流水不增加跳转，避免界面变成密集按钮列表。
- 错误信息不与分类排行混排。

## 五、组件边界

### 月份与命名模型

负责新旧月复盘名称解析、目标月份和目标路径生成。它不访问 Vault。

### 自动创建保障器

负责当前月判定、合法日记判定、存在性检查、并发锁和创建事务。它通过注入的 Vault 接口工作，不访问 UI 和 TickTick。

### 月任务模型

负责只读任务过滤、日期分组、统计和稳定排序。它返回纯数据，不创建 DOM。

### 月收支模型

继续负责金额、分类、坏数据和排序；增加前 5 分类与“其他”的展示投影。金额计算保持整数分，避免浮点误差。

### 月复盘 renderer

负责指标、任务筛选、日期时间轴、分类排行、折叠明细和错误来源按钮。所有用户文字使用 `textContent`，不注入不受信任 HTML。

### 插件生命周期

负责注册/释放 Vault create 监听、启动自检、设置变更即时检查，以及两个 Markdown processor 的 child 生命周期。插件卸载后不得迟到创建文件或写 DOM。

## 六、设置

新增布尔设置：`自动创建本月复盘`。

- 默认开启。
- 关闭时不执行启动补建，文件事件也不创建。
- 运行期间关闭后，后续事件立即遵循新值。
- 重新开启时立即检查当前月，满足条件则补建。
- 使用现有插件 settings/data 持久化机制。

## 七、安全边界

- 只允许创建精确计算出的当前月复盘路径。
- 不修改、覆盖、移动或删除已有文件。
- 不自动处理历史月份。
- 不依赖活动编辑器、当前焦点或 Templater UI。
- 不改变 TickTick 严格只读边界。
- 不修改 TickTickSync 文件或触发命令。
- 不改变每日模板 marker 或日记正文。
- processor 异常必须渲染可见中文错误，不能留下永久空块或 detached rejection。

## 八、测试设计

### 自动创建模型与事务

- 严格识别当前月合法日记路径和文件名。
- 排除历史月份、错误目录、错误文件名、非 Markdown 和月复盘。
- 生成带 `00` 的目标路径。
- 新旧名称任一存在时不创建、不重命名。
- 首篇日记创建一次，后续日记不重复。
- 启动时已有当前月日记但缺月复盘时补建。
- 没有当前月日记时不创建。
- 启动检查与 create 事件并发时只调用一次 Vault create。
- 写入前目标出现时不覆盖。
- 失败释放锁、无半成品、一次日志和一次中文 Notice。

### 月任务

- 仅计划日期或截止日期属于目标月的任务入选。
- created-only、无日期和其他月份任务排除。
- 已完成与未完成统计正确。
- 日期、定时、全天和稳定 tie 顺序正确。
- 日期分组、当天进度和三个筛选按钮行为正确。
- 筛选不调用任何 TickTick/Vault 写接口。

### 月收支

- 收入、支出、结余保持整数分统计。
- 支出分类降序，前 5 与“其他”合并正确。
- 百分比总量和零支出边界正确。
- 明细默认收起，展开后按日期分组，再次点击收起。
- 错误来源与正常流水分离。
- 小屏 DOM 为单列且无横向滚动。

### 集成与发布

- 新旧月复盘名称都能解析、渲染并从轮播排除。
- 设置默认、关闭和重新开启行为正确。
- 生命周期销毁后无迟到文件创建和 DOM 写入。
- TickTick 生产边界不存在写入、同步、完成、删除或命令调用。
- 自动正文与手动 Templater artifact 精确一致。
- development/install `main.js/styles.css` 字节一致。

## 九、实机验收

安装前完整备份 live HZ 插件，只覆盖 `main.js/styles.css`，核对 development/install/live 三端哈希。重载唯一用户 Vault 后，由用户手动执行：

1. 确认当前月月复盘不存在。
2. 创建当前月第一篇合法日记。
3. 确认 `YYYY年-MM-00-月复盘.md` 自动出现并排在最前。
4. 确认当前日记仍打开，只出现一次提示。
5. 确认月任务只含计划在本月的任务。
6. 确认任务日期时间轴与三个筛选清楚可用。
7. 确认收支分类排行、金额占比和折叠明细正确。
8. 再建日记并重载，确认不重复创建。
9. 关闭设置后确认不创建；重新开启后确认即时自检。
10. 在 iPhone 或窄窗口确认单列、无横向滚动。
11. 确认月复盘不进入日记轮播。

实机验收不得由自动化工具通过不可靠焦点插入模板或创建测试日记。
