# 月复盘模板与只读月度统计设计

## 背景

现有每日模板负责记录照片、柳比歇夫时间、随手记、收支、摘要以及 TickTick 任务。月复盘应复用这些已经形成的数据，而不是要求用户月底再次抄写。用户希望在电脑端获得完整统计，同时在 iPhone 上仍能清楚阅读和填写总结。

本设计新增一个月复盘模板，并由 HZ 个人工作台插件提供两个原生 Markdown 代码块处理器：`hz-month-tasks` 和 `hz-month-finance`。两块统计内容只读、动态生成，不写回月复盘 Markdown，也不修改 TickTick 或每日笔记。

设计参考了社区中“每日记录、周期笔记自动汇总、周期笔记只写反思”的常见方式，例如 [Periodic Note Templates](https://github.com/mulfok/periodic-note-templates) 与 [Obsidian Daily Note Templates](https://github.com/souravas/obsidian-daily-note-templates)。任务统计以 TickTick 的月度完成趋势思路为参考，但采用本地只读快照，避免触发同步或修改；TickTick 官方的 [Habit & Task Statistics](https://help.ticktick.com/articles/7082302534169133056) 和 [Task Details](https://help.ticktick.com/articles/7213444784319365120) 仅作为交互与字段语义参考。收支部分采用“总览、分类汇总、逐笔流水”三层结构，与社区的 [Obsidian 财务记录实践](https://forum.obsidian.md/t/financial-tracking-in-obsidian/86830) 一致；实现不依赖 Dataview，但查询边界参考其 [查询结构](https://blacksmithgu.github.io/obsidian-dataview/queries/structure/) 与 [数据命令](https://blacksmithgu.github.io/obsidian-dataview/queries/data-commands/)。

## 目标

- 从 TickTickSync 的本地任务仓库只读展示目标月份的全部任务。
- 从目标月份每日笔记的“今日收支”受控区域统计收入、支出、净额、支出分类及全部流水。
- 保留一组简洁的人工复盘栏目，让月复盘的重点仍是思考而非抄数据。
- 桌面端显示完整信息，iPhone 上使用单列卡片并保持可读、可填写。
- 历史月复盘始终按笔记自己的月份计算，不依赖电脑当前日期。
- 保持现有每日模板、TickTick 只读边界、日记轮播和移动记录流程不变。

## 非目标

- 不在月复盘中创建、修改、完成或删除 TickTick 任务。
- 不点击任务标题跳转 TickTick，也不调用 TickTickSync 的同步命令。
- 不修改每日笔记的收支记录，不做自动纠错。
- 不把动态统计固化或写入月复盘 Markdown。
- 不自动创建月复盘，不新增工作台入口或打开命令。
- 不统计“柳比歇夫时间记录”；“本月做的事情”以 TickTick 任务为唯一来源。
- 不支持人民币以外的币种，也不做预算、资产或账户余额管理。
- 不让月复盘进入每日回顾轮播。

## 文件与月份规则

### 模板与月复盘位置

- 模板路径：`07 模板/月复盘模板.md`。
- 月复盘与当月日记放在同一个月目录。
- 示例：`01 日记/2026年/8月/2026年-08月复盘.md`。
- 用户手动创建精确文件名后，通过 Templater 插入模板；插件不负责创建文件。

### Frontmatter

模板生成后的月复盘使用：

```yaml
---
type: 月复盘
month: 2026-08
tags:
  - 月复盘
---
```

### 目标月份解析

1. 优先读取合法的 `month: YYYY-MM`。
2. 缺少 `month` 时，允许从精确文件名 `YYYY年-MM月复盘.md` 解析。
3. frontmatter 与文件名同时合法但不一致时，显示明确错误并停止两个统计块渲染。
4. 两者都无法解析时，显示明确错误，不回退到电脑当前月份、文件创建时间或修改时间。
5. 目标月份的起止时间使用本地时区 `Asia/Shanghai` 的自然月边界。

这种“失败关闭”规则防止打开历史月报时悄悄统计成当前月份。

## 月复盘模板

模板正文结构为：

````markdown
# 2026年08月复盘

## 本月任务

```hz-month-tasks
```

## 本月收支

```hz-month-finance
```

## 本月总结

### 本月完成了什么

### 最重要的收获

### 遇到的问题

### 下月最重要的三件事
````

标题与 `month` 属性均由 Templater 根据月复盘文件名生成。文件名不合法时，模板应给出错误并停止填充月份，不猜测当前月。

## 本月任务

### 数据来源与只读边界

- 处理器通过已安装的 TickTickSync 插件实例取得本地 `taskRepository`，一次渲染只加载一次任务快照。
- 不扫描 Vault 中的 Markdown 任务作为回退来源。
- 不访问任务写入、完成、删除、同步或命令接口。
- TickTickSync 未安装、未登录、未初始化或仓库读取失败时，显示“TickTick 任务暂不可用，请检查 TickTickSync”，不影响手写总结和收支面板。
- 任务标题只作为纯文本渲染；没有 checkbox、链接、项目、清单、标签或优先级。

### 月份归属

- 有合法计划日期或截止日期的任务，按该日期归属目标月份。
- 没有计划/截止日期但有合法创建时间的任务，按创建日期归属目标月份，时间显示为“全天”。
- 两类日期都不存在或无法解析的任务不进入统计，并在面板底部显示“另有 N 项任务因缺少有效日期未归入本月”。
- 已完成和未完成任务都展示；不区分“逾期”。
- 历史月报在后续打开时仍读取最新本地快照，因此任务状态变化会动态更新，不做冻结快照。

适配层需要在现有规范化任务字段上增加只读的创建日期、开始时间和结束时间候选解析。不同 TickTickSync 版本字段不一致时，使用经过测试的候选字段顺序；无法可靠解析就降级为单时间点、全天或不可归入，不能猜测。

### 汇总

面板顶部显示：

- 任务总数；
- 已完成数；
- 未完成数；
- 完成率。

总数等于已完成数加未完成数。总数为零时，完成率显示 `0%`，避免显示无穷或空值。

### 明细格式与排序

状态位于每行最前方，只使用“已完成”和“未完成”：

```text
已完成｜2026年-08-19-星期三 9:00–10:00 事件
未完成｜2026年-08-20-星期四 14:30 事件
未完成｜2026年-08-21-星期五 全天 事件
```

时间显示规则：

- 有开始和结束时间：`9:00–10:00`；
- 只有一个可靠时间点：`14:30`；
- 没有可靠时间：`全天`。

排序顺序：

1. 日期升序；
2. 同日有时间的任务按开始时间升序；
3. 同日全天任务排在有时间任务之后；
4. 仍相同时按任务标题稳定排序。

不按日期分组，每行都显示完整日期，形成可连续浏览的月度时间线。全部符合条件的任务都保留在 DOM 中；内容较多时只让明细区滚动，不裁掉任务。

## 本月收支

### 数据来源

- 只读取目标月目录内 frontmatter 为 `type: 日记` 且日期属于目标月份的每日笔记。
- 每篇日记只解析现有 `hz:finance-entries:start` 与 `hz:finance-entries:end` 之间的受控流水。
- 不读取普通正文中看起来相似的金额，也不读取月复盘自身。
- 使用每日记录的既有格式：`- HH:mm｜收入/支出｜分类｜事项｜¥金额｜[[项目]]?`。
- 币种只接受人民币；金额用整数分计算，避免浮点误差。

### 汇总层级

面板按三层呈现：

1. 总览：本月收入、本月支出、本月净额；
2. 支出分类：按分类总金额降序，显示分类金额与占总支出的比例；
3. 全部流水：按日期、时间升序展示所有有效收入和支出。

流水格式：

```text
2026年-08-19-星期三 12:30｜支出｜餐饮｜午餐｜¥35.00
2026年-08-20-星期四 09:10｜收入｜其他｜退款｜¥88.00
```

可选的项目链接不进入显示和统计分组，避免面板过长；原始记录仍保留在每日笔记中。

### 无效记录

- 单条格式、时间、收支类型、金额或币种无效时，只排除该条；其余合法记录继续统计。
- 面板显示“发现 N 条无法统计的收支记录”。
- 同时列出包含无效记录的每日笔记，点击后在新标签页打开源日记并保留月复盘。
- 一个源日记只列一次，不重复刷屏。
- 解析失败不得修改源文件，也不得将无效金额按零元计入。

## 本月总结与编辑提示

四个手写栏目固定为：

- 本月完成了什么；
- 最重要的收获；
- 遇到的问题；
- 下月最重要的三件事。

空栏目分别显示编辑器装饰层的临时灰色提示：

| 栏目 | 提示 |
| --- | --- |
| 本月完成了什么 | 这个月真正完成了哪些重要事情？ |
| 最重要的收获 | 这个月最值得带走的经验或认识是什么？ |
| 遇到的问题 | 什么事情没有做好，原因是什么？ |
| 下月最重要的三件事 | 下个月最重要的三件事是什么？ |

- 提示不写入 Markdown，不参与同步、搜索或导出。
- 点击提示后重新解析当前文档，将光标放到对应标题后的安全空白行。
- 输入内容后提示立即消失，清空内容后恢复。
- 不预置 checkbox，避免被 TickTickSync 识别为任务。
- 设置新增独立开关 `显示月复盘编辑提示`，默认开启，切换后立即生效并持久化。
- 该开关与“显示日记填写提示”“显示日记技术标记”互不影响。

## 响应式与视觉设计

### 桌面端

- 任务汇总与收支总览使用紧凑指标行。
- 明细使用清晰的时间线/表格节奏，但不做复杂仪表盘。
- 状态、日期时间和标题建立稳定层级，长标题可换行。
- 大量任务和流水使用面板内部滚动，页面主体仍可自然滚动。

### iPhone

- 汇总指标自动换行或变为两列。
- 每条任务和收支转换为单列卡片，不依赖横向滚动。
- 日期时间、状态和标题分行显示，触控目标足够大。
- 四个总结栏目仍使用 Obsidian 原生 Markdown 编辑，不引入移动端专用表单。

所有颜色、边框、字号和焦点态使用 Obsidian 主题变量，兼容深色、浅色和墨影黑白；不得对照片或其他内容应用灰度滤镜。

## 架构

### 月份解析层

新增无 DOM 依赖的纯函数：

- 解析并校验 `month` frontmatter；
- 解析精确月复盘文件名；
- 检测冲突并返回明确错误；
- 生成目标月的本地日期边界和格式化信息。

### TickTick 月任务模型

在现有只读 TickTick 适配器边界内扩展字段归一化，然后由纯函数完成：

- 日期归属；
- 状态归一化；
- 时间区间降级；
- 汇总指标；
- 稳定排序；
- 不可归入计数。

处理器只接收最终视图模型并创建只读 DOM，不直接理解 TickTick 原始字段。

### 月收支模型

纯函数负责：

- 确定目标月的候选日记；
- 提取精确 marker 范围；
- 解析合法流水；
- 使用整数分汇总；
- 生成分类、流水和错误源笔记模型。

Obsidian 边界层负责读取文件和在新标签页打开错误来源；纯函数不访问 Vault。

### Markdown 处理器与生命周期

- 注册 `hz-month-tasks` 和 `hz-month-finance` 两个处理器。
- 每个代码块有独立的 Markdown render child。
- child 卸载或插件卸载后，迟到的异步结果不得继续更新 DOM。
- 打开笔记、切换阅读/实时预览或 Obsidian 重新渲染代码块时刷新数据。
- 不轮询、不自动触发 TickTickSync，也不保存动态结果。

### 日记轮播隔离

轮播的数据源必须继续只接受 `type: 日记`。`type: 月复盘`、文件名含“月复盘”的笔记及模板均不得进入日记卡片池。

## 空状态与错误状态

- 目标月没有任务：显示“本月暂无任务”，汇总为 0/0/0/0%。
- TickTickSync 不可用：显示可操作的检查提示，不显示伪造的零统计。
- 目标月没有有效收支：显示“本月暂无收支记录”，金额均为 `¥0.00`。
- 有效与无效收支混合：正常显示有效统计，同时显示无效记录告警和源笔记入口。
- 月份无效或冲突：两个面板都显示一致的月份错误，不扫描当前月。
- 单个日记读取失败：其他日记继续统计，并将该文件加入读取错误列表。

## 测试策略

### 月份与模板

- frontmatter 月份优先，文件名作为缺失时的回退。
- 两者冲突、格式无效、缺失时失败关闭。
- 模板生成正确标题、frontmatter、两个代码块和四个手写栏目。
- 月复盘不会进入轮播。

### 任务模型

- 已完成和未完成均归入。
- 有日期按计划/截止日期，未定日期按创建日期。
- 无任何有效日期的任务只计入不可归入数。
- 时间区间、单时间和全天三种格式正确。
- 日期、时间、全天、标题的稳定排序正确。
- 汇总总数、状态数和完成率保持一致。
- 标题以纯文本输出，DOM 无 checkbox、链接或写操作。
- 每块一次只读快照，TickTickSync 不可用时无 Vault 回退。

### 收支模型

- 只扫描目标月的 `type: 日记` 与精确 finance marker。
- 收入、支出、净额和分类汇总使用整数分且结果正确。
- 全部合法流水按日期时间排序。
- 无效格式、金额、币种和时间逐条隔离。
- 错误源笔记去重，并在新标签页打开且保留月复盘。
- 不修改任何源日记。

### 编辑提示、响应式与生命周期

- 四类空栏目提示精确出现、输入后消失、清空后恢复。
- 设置开关独立、即时、可持久化。
- 桌面和窄屏 DOM 保留全部数据且无横向溢出。
- child 销毁或插件卸载后禁止迟到渲染。
- 深色、浅色、墨影黑白使用主题变量和可见的 `focus-visible`。

## 发布与实机验收

1. 在受控月复盘中验证合法月份、冲突月份与历史月份。
2. 对照 TickTick 本地任务确认总数、状态、日期、时间与排序；不触发同步或修改。
3. 对照至少两篇每日笔记确认收入、支出、净额、分类与全部流水。
4. 使用一条临时无效收支验证告警和“新标签页打开源日记”，随后恢复源文件。
5. 在桌面宽度与 iPhone 窄宽下验证无裁切、无横向滚动、长标题可读。
6. 验证四个提示的点击、输入、撤销与设置持久化。
7. 验证月复盘不进入日记轮播。
8. 验证 TickTickSync 不可用、空任务和空收支状态。
9. 完整语法检查、自动化测试、构建和发布包一致性检查全部通过。
10. 安装前完整备份 HZ 插件；只覆盖必要发布产物；确认 `data.json`、logo、模板、日记、TickTickSync 和布局未被意外修改。

只有自动化、发布产物和实际 Obsidian 验收全部通过，才宣称月复盘功能完成。

## 已确认的取舍

- 采用 HZ 插件原生 Markdown 处理器，不使用 DataviewJS，也不生成静态快照。
- 动态结果随 TickTick 和日记数据变化而更新，历史月报不冻结。
- 月份严格来自月复盘自身，不使用电脑当前月份。
- TickTick 只读展示全部任务；未定日期任务按创建日期归月。
- 收支只来自每日笔记的受控记录，币种仅人民币。
- 模板通过 Templater 手动创建，不增加插件创建入口。
- 月复盘的核心人工内容是四个总结问题，统计数据不需要重复填写。
