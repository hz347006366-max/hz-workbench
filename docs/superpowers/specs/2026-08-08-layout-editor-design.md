# HZ 个人工作台：自由布局与无闪动日记轮播设计规格

日期：2026-08-08  
状态：设计已逐段确认并完成自审

## 1. 背景

HZ 个人工作台 v0.1.0 已包含日记热力图、日记 3D 轮播、项目区、今日必完成、任务列表、主题配色和 TickTickSync 联动。本次设计同时解决两项体验问题：

1. 用户需要在桌面版 Obsidian 中自由拖动全部工作台模块，使用细网格吸附并进行严格等比例缩放；布局按设备独立保存。
2. 当前日记轮播每次切换都会调用工作台的完整 `render()`。该方法先执行 `root.empty()`，再重新读取数据并重建侧栏、统计卡、项目区和任务区等全部 DOM，导致整个工作台产生刷新式闪动。

轮播问题已经在当前 macOS Obsidian 中进行实机观察，并通过 `moveCarousel → render → root.empty()` 调用链定位。应用日志中没有与轮播相关的运行错误，现有 CSS 也没有整页切换动画，因此根因是错误地使用整页渲染路径，而不是单张图片解码失败。

## 2. 目标

- 用户长按模块 500ms 即可进入布局编辑，不需要显式“编辑布局”按钮。
- 十个模块均可自由拖动，并吸附到细网格、画布边界、相邻模块边缘、中心线和标准间距。
- 模块只能严格等比例缩放；容器、文字、图标、间距和圆角一起缩放。
- 调整过程中允许暂时重叠，但存在重叠时不能保存或退出编辑。
- 单击画布空白处自动校验、保存并退出。
- 每台电脑使用独立布局；Windows、Mac 以及两台同系统电脑互不覆盖。
- 同一设备改变 Obsidian 窗口大小时，整张布局按宽度同比显示。
- 日记轮播支持年份和月份筛选，每月最多展示最近 30 篇。
- 轮播切换只更新稳定卡片池，不能重建工作台其他模块或改变滚动位置。
- 现有日记、项目、任务、TickTickSync、主题和导航业务规则不退化。

## 3. 非目标

- 本版不支持手机和平板上的触控布局编辑；移动端继续使用默认响应式布局。
- 不引入 GridStack、interact.js 等第三方拖拽或布局库。
- 不允许非等比拉伸模块。
- 不自动推挤或重排发生冲突的模块。
- 不允许保存重叠布局。
- 不改变日记解析、项目筛选、任务筛选或 TickTickSync 的数据规则。
- 不在画布外常驻渲染 30 张日记卡片。

## 4. 可调整模块

每个布局单元使用不会随文案或 DOM 层级变化的稳定 ID：

| 模块 ID | 模块名称 |
| --- | --- |
| `sidebar` | 左侧导航与 Logo |
| `header` | 顶部问候与操作区 |
| `stat-today-tasks` | 今日任务统计卡 |
| `stat-active-projects` | 进行中项目统计卡 |
| `stat-today-schedule` | 今日日程统计卡 |
| `stat-journal-streak` | 连续日记热力图卡 |
| `journal-carousel` | 日记 3D 轮播区 |
| `projects` | 进行中的项目区 |
| `must-do` | 今日必完成区 |
| `today-tasks` | 今日任务列表区 |

新增模块必须提供稳定 ID、默认矩形、基础内容尺寸、最小缩放比例和宽高比，才能加入自由布局画布。

## 5. 技术方案与模块边界

采用原生逻辑画布与 Pointer Events，不引入布局库。现有 `src/main.js` 只保留插件生命周期、工作台视图编排和业务模块渲染入口。新增以下独立单元：

### 5.1 `layout-model.js`

负责默认布局、模块定义、逻辑坐标、边界修正、碰撞检测、吸附候选计算、设备布局校验、格式迁移和显示比例换算。该模块不访问 DOM。

### 5.2 `layout-controller.js`

负责长按识别、编辑状态机、拖动、等比缩放、吸附选择、冲突状态、撤销栈、取消、恢复默认和保存请求。Pointer Events 只在该层转换为逻辑坐标操作。

### 5.3 `layout-store.js`

负责生成和读取本地设备 ID、按设备文件读取与原子写入布局、恢复文件和格式迁移的持久化步骤。该模块不参与坐标计算。

### 5.4 `layout-view.js`

负责编辑边框、模块名称、缩放手柄、网格、吸附参考线、重叠斜纹、长按进度和浮动工具栏。它消费控制器状态，不决定坐标规则。

### 5.5 `carousel-controller.js`

负责年月索引、当前月份、当前日记、七卡片循环池、自动轮播、滚轮节流、拖动切换、图片预解码、前后台暂停和布局编辑期间暂停。轮播移动不得调用工作台完整 `render()`。

### 5.6 工作台视图

现有业务渲染函数继续创建模块内容，但每个模块外增加布局壳层和统一缩放内容层。工作台视图负责把业务数据传入模块，不处理拖拽数学或轮播队列。

## 6. 布局数据模型

逻辑画布宽度固定为 1440 单位。模块使用绝对定位，画布高度由最下方模块的底边加安全留白自动计算。持久化数据只保存位置和单一缩放比例，实际宽高始终从模块定义推导，避免宽、高、比例三者不一致。

```text
StoredModuleLayout = {
  x,
  y,
  scale
}

ComputedLayoutRect = {
  x,
  y,
  width: module.baseWidth * scale,
  height: module.baseHeight * scale
}
```

- `x`、`y` 使用逻辑单位，不保存设备像素。
- `scale` 表示模块内容相对基础尺寸的整体比例。
- 宽度、高度和宽高比来自稳定模块定义，不在设备布局中重复保存。
- 外层布局壳层占据缩放后的实际矩形；内层内容以左上角为原点统一缩放。
- 交互内容较密集的 `must-do` 和 `today-tasks` 最小模块比例为 0.75。
- 其他模块最小模块比例为 0.65。
- 单个模块最大比例为 2.0，同时不能超过画布宽度或进入负坐标。

## 7. 窗口适配

```text
viewScale = availableWidth / 1440
```

- 正常情况下，位置、模块尺寸和内容按 `viewScale` 一起显示。
- `viewScale` 最低为 0.68；可用宽度更小时不再压缩内容，改为允许横向滚动。
- 画布始终允许纵向滚动。
- 窗口尺寸变化只更新显示比例，不改写逻辑布局，也不触发磁盘保存。
- 普通模式和编辑模式共用同一逻辑坐标，进入编辑时模块不能跳位。
- 移动端不读取桌面设备布局，不创建绝对定位画布，也不注册长按编辑事件；继续使用现有响应式布局。
- 默认桌面布局必须复现 v0.1.0 当前模块位置和视觉比例，首次升级不能出现无理由跳位。

## 8. 长按与编辑状态机

状态依次为：`idle → arming → editing → dragging/resizing → editing`。

### 8.1 进入编辑

- 仅响应鼠标主键；在任意模块的非交互区域按住 500ms 进入编辑。右键、中键、触控指针和带修饰键的点击不触发。
- 长按期间在指针附近显示轻量进度环。
- 按住期间移动超过 6px、提前松开、指针离开窗口或收到取消事件时回到 `idle`。
- `button`、`input`、`textarea`、链接、任务项、轮播卡片、滚动条和带有交互标记的后代节点不启动长按。

### 8.2 编辑中

- 模块主体用于拖动。
- 在编辑模式中按下另一个模块会先将其设为当前模块；移动超过 3px 后开始拖动，未超过 3px 的点击只切换当前模块。
- 当前模块右下角显示缩放手柄；手柄视觉尺寸约 16px，命中区域不小于 32px。
- 编辑期间屏蔽模块内部点击、输入、轮播滚轮和卡片打开行为。
- 当前操作模块置于最高层，其他模块不自动移动。
- 一次完成的拖动或缩放形成一条撤销记录；最多保存最近 30 条内存记录。

### 8.3 保存与退出

- 只有事件目标直接是布局画布背景时才视为“单击空白处”；模块、工具栏、参考线、滚动条及其后代节点都不触发保存，工具栏事件必须停止冒泡。
- 单击画布空白处时执行完整校验。
- 无重叠且数据有效时，一次性写入当前设备布局并退出。
- 存在重叠时保持编辑状态，冲突模块变红，并使用 Obsidian 通知提示“存在重叠，无法保存”。
- 浮动工具栏包含“撤销”“恢复默认”“取消调整”。
- “恢复默认”只将默认布局载入内存，仍需单击空白处才能保存。
- “取消调整”恢复进入编辑前的快照并退出，不写磁盘。
- `Esc` 等同“取消调整”。
- 保存成功后显示“布局已保存到当前设备”。

## 9. 拖动、吸附与碰撞

### 9.1 网格

- 基础网格为 8×8 逻辑单位。
- 指针的屏幕坐标先除以当前 `viewScale`，再参与布局计算。
- 拖动过程更新内存预览，松手后才提交一条撤销记录。

### 9.2 吸附

距离候选目标 8 逻辑单位以内时触发磁性吸附。吸附优先级固定为：

1. 画布左、上、右边界。
2. 相邻模块外边缘和水平、垂直中心线。
3. 与相邻模块保持 8 或 16 单位标准间距的位置。
4. 8×8 基础网格。

同一优先级存在多个候选时，选择指针位移最小的候选；位移相同则按稳定模块 ID 排序，保证结果可重复并避免抖动。

### 9.3 边界与碰撞

- 模块不能越过画布左侧或顶部。
- 模块右边界不能超过 1440。
- 模块边缘相接不算重叠；交集面积大于零即视为冲突。
- 操作中允许暂时重叠，不自动推开其他模块。
- 保存校验会再次使用最终缩放矩形进行全量两两碰撞检测。

## 10. 等比例缩放

- 缩放只使用右下角手柄，左上角保持固定。
- 水平与垂直指针位移换算为单一缩放比例，选择最接近指针方向且满足边界的比例。
- 宽度和高度始终由基础尺寸乘以同一个比例得到。
- 缩放预览和最终结果都执行最小比例、最大比例、画布边界与碰撞检查。
- 松手时尺寸先按比例限制，再参与边缘、标准间距和网格吸附。吸附只调整单一缩放比例，不能分别取整宽度和高度。
- 模块内容、字号、图标、间距、圆角和内部阴影使用统一缩放层，不能发生内容重排式缩放。

## 11. 编辑界面视觉规范

- 编辑模式使用轻微半透明暗色遮罩压低内容，但不改变主题变量。
- 所有模块显示 1px 主题强调色边框；当前模块使用 2px 边框和轻微外发光。
- 模块名称使用小号半透明标签固定在左上角。
- 吸附参考线使用低透明度虚线；中心对齐和标准间距显示短标签。
- 冲突模块使用现有危险色，重叠区域附加斜纹，不能只依赖颜色表达错误。
- 浮动工具栏以不参与布局和碰撞的覆盖层固定在画布可视区域顶部中央，并显示“单击空白处保存并退出”。
- 开启“减少动态效果”时移除发光、渐变过渡和吸附动画，但保留边框、标签、斜纹和文字提示。

## 12. 按设备保存

首次使用时生成随机本地设备 ID，保存到 Obsidian 应用本地存储键 `hz-workbench:device-id:v1`。设备 ID 不包含设备名、用户名、屏幕参数或硬件信息。

自审发现：若把所有设备布局放在同一个 `data.json`，两个尚未完成同步的设备先后保存时，后写入的完整文件仍可能覆盖另一设备的新布局，无法严格满足“设备互不覆盖”。因此布局改为每个设备一个独立文件；`data.json` 只保存现有插件设置。

布局目录使用 Obsidian 当前配置目录，而不是硬编码 `.obsidian`：

```text
<vault-config-dir>/hz-workbench/layouts/<deviceId>.json
<vault-config-dir>/hz-workbench/layouts/<deviceId>.recovery.json
```

单个设备布局文件结构：

```text
{
  schemaVersion: 1,
  deviceId,
  canvasWidth: 1440,
  modules: Record<moduleId, StoredModuleLayout>,
  updatedAt
}
```

- 保存使用同目录临时文件，写入和校验完成后再以重命名替换正式文件；失败时保留旧文件。
- 不同设备只写各自的 `<deviceId>.json`，因此同步仓库时不会产生同一布局文件的写入竞争。
- 编辑状态、长按状态和撤销历史只存在内存中。
- 应用在编辑过程中异常退出时，未完成调整丢弃，上次有效布局保持不变。
- 设备 ID 必须是随机 UUID，并在组成文件名之前通过 UUID 格式校验。设备 ID 丢失时生成新 ID，并把当前电脑视为新设备；原布局文件保留，不自动删除。
- 缺少模块时补入默认布局；未知模块保留但不渲染；非法数字、比例和边界自动修正。
- 单个设备布局完全不可解析时，将原始值覆盖保存到当前设备的 `.recovery.json`，当前设备回退默认布局并显示通知。
- 格式版本迁移必须逐版本执行；迁移失败不能覆盖最后一份有效布局。

## 13. 年月筛选与日记数据队列

### 13.1 筛选规则

- 日记按本地日期的 `YYYY-MM` 分组，每组按日期倒序排列；日期相同时按规范化文件路径升序排列，保证顺序稳定。
- 年份下拉框只列出存在日记的年份。
- 月份下拉框只列出选中年份中存在日记的月份。切换年份时自动选择该年最近的有效月份。
- 首次打开默认选择最近有日记的月份，不记忆上次选择。
- 每个月最多进入队列 30 篇；超过 30 篇时保留日期最新的 30 篇。
- 切换年份或月份后，当前索引回到该月最新一篇，并重新开始自动轮播计时。
- 某月不足 5 篇时只显示实际篇数并居中，不重复日记、不生成占位卡。

### 13.2 稳定七卡片池

- 30 篇只保存在内存数据队列中，不创建 30 个 DOM 卡片。
- 队列多于 5 篇时最多创建 7 个稳定卡片节点：5 个可见槽位，左右各 1 个画布外预备槽位。
- 队列不超过 5 篇时只创建实际数量的卡片节点。
- 前进或后退只修改卡片槽位类与 transform，不清空轮播区，也不调用工作台完整 `render()`。
- 350ms 位置动画结束后，回收离场卡片，将其内容替换为队列下一篇并放入另一侧预备槽位。
- 当前卡片和相邻可见卡片优先加载；下一预备图片通过 `requestIdleCallback` 调度并使用 `Image.decode()` 预解码。环境不支持 `requestIdleCallback` 时使用零延迟定时器，`decode()` 不可用时回退到 `load`/`error` 事件。
- 图片未解码时保留现有渐变背景；加载成功后只在该卡片内淡入。
- 单张图片加载失败时只影响对应卡片，不触发轮播或工作台重渲染。

### 13.3 输入与生命周期

- 自动轮播、鼠标滚轮和水平拖动共用一个 `CarouselController.move(direction)` 入口。
- 自动轮播继续使用插件现有 `carouselSeconds` 设置，非法值回退为 6 秒，有效值不得小于 3 秒。
- 动画期间设置切换锁；额外滚轮输入按方向最多保留一步，防止动画重叠。
- 滚轮增量按 `deltaMode` 归一化为 CSS 像素，同方向累计达到 40px 才切换一次；方向改变时清空累计值。一次切换后等待 350ms 动画结束再接受下一步。
- 水平拖动距离达到 35 CSS px 才切换；不足阈值时卡片回到原位。
- 进入布局编辑模式时暂停轮播并禁用轮播输入；退出后从当前卡片恢复。
- Obsidian 标签页不可见或工作台视图失活时暂停定时器；重新可见时重新计时，不补播错过的次数。
- 开启“减少动态效果”时停止自动轮播；手动切换直接更新槽位，不播放位移动画。

## 14. 数据刷新与轮播隔离

- 日记、任务或项目数据更新不能由轮播定时器触发。
- Vault 与 metadataCache 事件继续使用去抖刷新，但刷新应按模块数据域更新，不能无条件清空工作台根节点。
- 日记索引刷新后按规范化文件路径保留当前日记；该文件被删除时保留原数组索引，并将索引限制到新队列范围内。
- 当前年月已经没有日记时，回退到最近有日记的月份。
- 布局编辑过程中收到数据刷新事件时，只记录待刷新标记；保存或取消退出编辑后再刷新业务内容，避免销毁拖拽状态。
- 主题切换可以更新工作台主题类和必要内容，但不能借用轮播切换路径。

## 15. 错误处理

- 长按定时器、轮播定时器和图片预载任务必须在视图关闭时全部清理。
- 重复进入编辑请求会被忽略。指针取消、窗口失焦、视图隐藏或拖动期间窗口尺寸变化时，当前手势回到该次手势开始前的编辑快照，编辑模式继续保持。
- 保存失败时保持编辑状态和内存布局，提示用户重试或取消，不能假装保存成功。
- 轮播队列为空时显示现有空状态，并保留年月筛选区域的稳定尺寸。
- 年月索引含无效日期的日记不进入轮播，但不得阻止其他日记显示。

## 16. 自动测试

### 16.1 布局模型

- 默认布局包含全部十个稳定模块 ID，且没有越界或重叠。
- Windows、macOS 和两台同系统设备生成不同 UUID，并只读写各自的布局文件。
- 两个设备基于尚未同步的目录分别保存后，同步结果同时保留两个设备布局文件。
- 缺失、未知、非法和旧版本布局可以补全、保留、修正或迁移。
- 8×8 网格、边缘、中心线和标准间距吸附遵守固定优先级。
- 相同吸附候选得到确定性结果。
- 边缘相接不冲突，交集面积大于零即冲突。
- 等比例缩放始终保持宽高比，并遵守模块比例和画布边界。
- 窗口变化只改变显示比例，不修改逻辑坐标。

### 16.2 编辑控制器

- 499ms 不进入编辑，500ms 进入编辑。
- 提前松开、移动超过 6px、取消事件、非鼠标主键、触控指针、修饰键和交互控件按下均不触发编辑。
- 一次拖动或缩放只创建一条撤销记录，撤销栈最多 30 条。
- 有冲突时空白点击不能保存或退出。
- 无冲突时空白点击只写盘一次并退出。
- 撤销、恢复默认、取消调整和 `Esc` 得到正确快照。
- 普通模式不渲染编辑边框、标签、手柄、网格、参考线或工具栏。

### 16.3 轮播控制器

- 年份和月份索引只包含实际存在日记的年月。
- 默认月份是最近有日记的月份。
- 单月 1、4、5、30 和超过 30 篇时，队列和可见卡片数量正确。
- 超过 30 篇时只保留最近 30 篇。
- 切换年月只更新筛选控件和轮播卡片池。
- 切换年份自动选择该年最近月份；同日期日记按文件路径稳定排序。
- 自动、滚轮和拖动切换共用同一移动入口，切换锁不会丢失最终状态。
- 滚轮累计 39px 不移动，累计 40px 移动一步；水平拖动 34px 不移动，35px 移动一步。
- 图片加载失败不影响其他卡片。
- 编辑模式、后台标签页和减少动态效果正确暂停轮播。
- 轮播切换不得调用工作台完整 `render()`。
- 轮播切换前后，工作台根节点、侧栏、统计卡、项目区和任务区保持同一 DOM 引用。

### 16.4 回归测试

- 现有 15 项数据与 UI 测试必须继续通过。
- 任务输入、轮播卡片点击、文件跳转、主题切换、TickTickSync 和业务数据刷新保持原有功能。

## 17. 实机验收

### 17.1 macOS

1. 分别长按十个模块，确认均能从非交互区域进入编辑。
2. 验证长按取消阈值以及按钮、输入框、任务项和轮播卡片排除规则。
3. 拖动模块并观察边界、边缘、中心线、标准间距和网格吸附。
4. 对各类模块进行等比例缩放，确认文字、图标和间距一起缩放。
5. 制造重叠，确认空白点击无法保存或退出。
6. 依次验证撤销、恢复默认、取消调整与 `Esc`。
7. 单击空白保存，重启 Obsidian 后布局保持。
8. 改变窗口宽度，确认整张布局同比显示且逻辑位置不变。
9. 在不同年份和月份之间切换，确认默认月份、30 篇上限和不足 5 篇居中规则。
10. 连续观察自动轮播，并使用滚轮和拖动切换；工作台其他模块不得闪动、销毁或改变滚动位置。
11. 在轮播切换时进入布局编辑，确认轮播立即暂停，退出后恢复。
12. 验证任务输入、笔记跳转、项目打开、主题和 TickTickSync 未退化。
13. 开启减少动态效果，确认编辑反馈仍清晰，轮播不自动播放。

### 17.2 Windows

- 自动测试模拟 Windows 平台和独立设备 ID。
- 在原 Windows 电脑上补做一次桌面实机验收，重点检查 Pointer Events、长按阈值、系统缩放比例、滚轮方向和设备布局隔离。

## 18. 完成标准

用户无需修改 CSS 或进入插件设置，即可长按任意模块的非交互区域进入布局编辑；所有模块都可自由拖动、细网格吸附和整体等比例缩放。无冲突布局可通过单击空白处自动保存到当前设备，重启与窗口缩放后保持正确。

日记区可按年份和月份选择每月最近 30 篇，并通过最多七个稳定卡片节点连续轮播。自动切换、滚轮切换和拖动切换均不得触发工作台整页渲染，工作台其他模块不得闪动、重建或改变滚动位置。

## 19. 实施拆分

两项能力在同一版本交付，但按以下顺序分阶段实施和验证，避免把轮播回归与布局交互混在一次改动中：

1. 建立稳定模块 DOM 边界，实现年月索引和七卡片轮播控制器，先消除整页闪动。
2. 实现纯函数布局模型、独立设备布局存储和迁移测试。
3. 实现长按状态机、拖动、吸附、等比缩放和编辑覆盖层。
4. 连接轮播暂停与布局编辑状态，执行完整自动测试和 macOS 实机验收。

每一阶段完成后都必须通过现有测试和该阶段新增测试，才能进入下一阶段。Windows 实机验收作为同版本发布前的最终检查项。
