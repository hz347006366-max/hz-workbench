# HZ 工作台智能体占位、记录入口与日记直建设计

日期：2026-08-24  
状态：用户已确认设计与规格，并授权直接实施  
适用插件：HZ 个人工作台 0.3.x

## 一、目标

本轮同时完成三组相互关联的改动：

1. 精简工作台左侧区域，只保留独立 Logo，并新增一个可供未来接入个人智能体的占位卡片。
2. 将右上角 `+` 改为“记录今日”入口，复用现有七项记录菜单。
3. 取消 HZ 对 Daily Notes 与 Templater 的创建依赖，由插件读取可配置模板并直接创建今日日记。

此外，移除已经没有决策价值的辅助说明文字，并缩小“设为必完成 / 取消必完成”按钮，降低界面噪音。

## 二、明确不在本轮范围内的内容

- 不接入任何真实智能体、模型、API 或网络服务。
- 不保存对话，不提供本地伪对话或模拟回复。
- 不修改 TickTick 任务，不触发 TickTickSync 同步。
- 不重新设计“记录今日”七个动作的业务表单。
- 不修改月复盘的数据规则和展示逻辑。
- 不恢复日记的“上一篇 / 下一篇”导航。

真实智能体接入应作为后续独立项目，单独确认模型来源、隐私边界、权限、费用和会话存储。

## 三、工作台界面

### 3.1 Logo 模块

- 删除左侧“今日、日记、项目、领域、资源、归档”六个按钮。
- 删除底部 `HZ / 个人工作台` 个人区域。
- 保留透明 PNG Logo，不增加白底、文字或额外装饰。
- 将原来的长条侧栏改成紧凑方形 Logo 卡片。
- 保留现有 `sidebar` 模块 ID，用于兼容已有布局数据；用户可见名称改为 `Logo`。
- Logo 卡片继续参与自由布局，可拖动和等比例缩放。

### 3.2 智能体占位卡片

新增独立模块 `agent-panel`，默认位于 Logo 下方，基础尺寸为 `306 × 760px`，并支持自由拖动和等比例缩放。

卡片只展示：

- 标题：`HZ 智能体`
- 状态：`待接入`
- 空状态：`这里将用于与个人智能体对话`
- 一个禁用的输入框外观
- 一个禁用的发送按钮外观

卡片不得接受输入、保存文字、发起网络请求或伪造智能体回复。禁用状态需要具备明确的视觉与可访问语义。

### 3.3 顶部操作区

- 搜索按钮保持现状。
- 配色按钮保持现状。
- `+` 图标保持现状，但无障碍标签和提示文字改为 `记录今日`。
- 点击 `+` 调用现有 `openDailyCapture()`，打开“记录今日 · 选择内容”菜单。

菜单继续包含以下七项，顺序不变：

1. 今日照片
2. 开始计时
3. 结束当前计时
4. 补记时间
5. 随手记
6. 记录收支
7. 打开今日日记

### 3.4 辅助文字与按钮密度

以下工作台辅助文字不再渲染：

- 今日任务统计卡下方的 TickTickSync 缓存来源说明。
- 进行中项目统计卡下方的“缺少下一步”等脚注。
- 今日日程统计卡下方的来源说明。
- 日记轮播下方的自动轮播与操作说明。
- 今日必完成卡片底部的 TickTickSync 缓存说明。
- 今日任务卡片中的 TickTickSync 缓存来源说明。

统计数字、状态徽标、任务本身和错误状态仍保留。数据源真正不可用时，仍必须显示明确错误，不能因隐藏常态说明而隐藏故障。

“设为必完成 / 取消必完成”改为紧凑型低强调按钮：

- 高度约 28–30px。
- 缩小字体和水平内边距。
- 保持清晰的键盘焦点样式和移动端可点区域。
- 不改变本地选择、最多三项和 TickTick 只读边界。

## 四、自由布局与迁移

### 4.1 新布局结构

- 桌面逻辑画布由 `1440px` 扩宽到 `1640px`，为智能体区域提供真实空间。
- `sidebar` 改为基础尺寸 `112 × 112px` 的 Logo 卡片，默认位置保持 `{ x: 16, y: 16, scale: 1 }`。
- `agent-panel` 默认位置为 `{ x: 16, y: 144, scale: 1 }`，与 Logo 保持 `16px` 间距。
- 原有 header、统计卡、轮播、项目、今日必完成和今日任务模块的默认 `x` 统一增加 `194px`；`y`、尺寸和 `scale` 不变。
- 原有模块的尺寸、垂直关系和缩放比例尽量保持不变。
- 新默认布局必须通过边界和冲突校验。

### 4.2 旧布局迁移

- 布局文档由 schema `1` 升级到 schema `2`。
- 读取到合法的 schema `1` 文档后，在变换前将原始 JSON 写入同目录的 `<deviceId>.schema-v1.backup.json`。备份文件若已存在则不得覆盖，以保留最初的旧布局。
- 首次备份写入失败时中止迁移并保留原布局文件，不能在没有可恢复副本的情况下继续。
- `sidebar` 数据迁移为方形 Logo 模块。
- 缺少 `agent-panel` 的旧布局自动补入该模块。
- 其他已知模块的 `x` 增加 `194px`，并保留原有 `y` 和 `scale`。
- 迁移结果必须通过完整布局校验；出现冲突或越界时，回退到新的无冲突默认布局，并给出一次中文提示。
- schema `1` 中未知的模块 ID 及其完整 payload 继续保留，不因本次迁移丢失；已知模块仍只接受 `x`、`y`、`scale` 三个布局字段。
- JSON 无法解析时继续使用现有 `.recovery.json` 恢复机制；这类损坏文件不伪装成 schema `1` 备份。

### 4.3 响应式布局

小于桌面断点时不使用扩宽横向画布：

1. Logo
2. HZ 智能体占位卡
3. 顶部问候与操作区
4. 统计卡
5. 日记轮播
6. 项目
7. 今日必完成
8. 今日任务

智能体卡在移动端宽度跟随容器，输入框和发送按钮仍保持禁用。不允许出现横向滚动。

## 五、日记模板设置

### 5.1 设置项

新增文本设置：

- 名称：`日记模板路径`
- 默认值：`07 模板/每日模板.md`
- 路径相对于当前 Vault。

路径在保存时规范化，但不静默改写到其他模板。路径无效时保留用户设置，并在实际创建时显示明确错误。

### 5.2 移除 Templater 导航

从以下位置删除：

```text
<%* tR += await tp.user.journal_navigation.run(tp); %>
```

至少同步更新：

- `F:\Obsidian\07 模板\每日模板.md`
- 仓库内发布使用的每日模板资产
- 对应模板测试基线

现有日记不批量改写。`journal_navigation.js` 可暂时保留为未使用脚本，本轮不删除，以免扩大清理范围。

## 六、受控模板渲染

### 6.1 支持的变量

HZ 只解析形式为 `{{date:FORMAT}}` 的日期变量。`FORMAT` 只允许组合：

- `YYYY`
- `MM`
- `DD`
- `dddd`
- 普通中文、空白字符，以及固定安全标点 `- _ / . : （ ） ( )`

解析器按最长 token 优先扫描。除上述四个 token 与允许的字面字符外，任何 ASCII 字母、数字、花括号、尖括号或其他字符均拒绝；`FORMAT` 不允许为空。

`dddd` 输出中文完整星期，例如 `星期一`。

当前模板应得到：

- `{{date:YYYY-MM-DD}}` → `2026-08-24`
- `{{date:YYYY年-MM-DD-dddd}}` → `2026年-08-24-星期一`

### 6.2 严格拒绝

出现以下任一情况时停止创建：

- 任何未知 `{{变量}}`。
- 日期格式含不支持的 token。
- 任何 `<% ... %>`、`<%* ... %>` 或其他 Templater 代码。
- YAML frontmatter 未闭合。
- 模板不是规范日记结构。
- 必要的 HZ managed marker 缺失、重复、交叉或逆序。
- `hz-tasks` 今日任务与明日行动块不符合既有模板契约。

不得把未知变量或 Templater 代码原样写入新日记。

### 6.3 模板验证复用

模板渲染和结构校验应放在独立纯函数模块中，并复用或扩展现有 `validateDailyTemplate()` 规则。渲染必须在任何目录或文件写入之前完成。

## 七、打开或创建今日日记

### 7.1 查找现有日记

调用“打开今日日记”时：

1. 使用当前本地日期生成 `YYYY-MM-DD`。
2. 继续使用现有 `findJournal()` 与严格日记日期解析寻找当天日记。
3. 如果存在，直接在新标签页打开。
4. 不读取模板，不修改日记，不重写导航或 frontmatter。

### 7.2 直接创建

如果当天日记不存在：

1. 读取 `日记模板路径`。
2. 完成变量解析和结构校验。
3. 使用既有路径规则生成目标：  
   `01 日记/YYYY年/M月/YYYY年-MM-DD-星期X.md`
4. 再次检查当天日记和目标路径，防止竞态。
5. 创建缺失的年月目录。
6. 通过 Vault API 创建完整日记。
7. 等待 Vault 与 metadata cache 可识别该文件。
8. 在新标签页打开，保留工作台。

不得调用 `daily-notes` 命令，不依赖 Templater，不依赖当前编辑器焦点。

### 7.3 共享创建行为

现有照片、随手记、时间和收支动作都依赖 `ensureJournal()`。本轮将 `ensureJournal()` 的缺失日记路径统一切换到直接创建，因此七项记录入口使用同一份稳定逻辑。

### 7.4 并发与幂等

- 同一日期同时触发的创建请求共享一个 in-flight Promise。
- 写入前必须二次检查现有日记与精确目标路径。
- 只允许一次 `vault.create()`。
- 成功后所有等待调用方获得同一个文件。
- 失败后释放锁，允许用户修正模板后重试。
- 插件卸载后不得继续打开标签页或显示迟到成功提示。

### 7.5 月复盘联动

新日记通过 Vault API 创建后，现有 create 事件继续触发月复盘检查。本轮不为月复盘增加特殊调用或第二条创建路径。

## 八、错误处理

用户可见错误使用简短中文 Notice，并在控制台记录原始异常：

- 模板文件不存在或不可读取。
- 模板含不支持的变量或 Templater 代码。
- 模板结构不合格。
- 目标路径已被非日记文件占用。
- 目录创建失败。
- 日记创建失败。
- 创建后文件无法被 Vault 识别。
- 新标签页打开失败。

模板验证失败时不得创建目录或文件。文件创建成功但打开失败时，应明确提示“日记已创建，但打开失败”，不得删除已创建的用户文件。

## 九、组件边界

建议拆分为以下单一职责单元：

1. `daily-template-renderer`：解析日期变量、拒绝未知模板语法、调用结构验证。
2. `daily-journal-ensurer` 或扩展后的 `DailyCaptureService.ensureJournal()`：查找、并发、目录与创建编排。
3. `layout migration`：只处理旧布局到新布局的数据变换，不创建 DOM。
4. `agent placeholder renderer`：只渲染无状态、禁用的占位界面。
5. `WorkbenchView`：连接 `+`、Logo、智能体卡和既有记录菜单。

这些单元应通过明确参数通信，避免把模板解析、Vault 写入和 UI 状态继续堆进 `main.js`。
