# HZ 个人工作台项目系统设计

日期：2026-09-02  
状态：已确认

## 1. 目标

将 `02 项目` 整理为统一、可扩展的项目管理体系，并把项目总览与项目驾驶舱原生集成到 HZ 个人工作台。

系统必须坚持“一份 Markdown 数据，多种自动视图”：项目属性只保存在项目主页，阶段属性和细项只保存在阶段笔记；项目卡、进度、甘特图、财务与最近记录均从这些文件实时计算，不保存重复副本。

首个落地项目为“省地勘局宿舍”。该项目不迁移旧视图，也不保留备份；直接删除旧结构后，使用现有 15 个阶段名称、细项和材料提醒重建为新模板。

## 2. 已确认的产品决策

- 工作台左侧删除智能体内容，但保留完整的空白功能栏，供未来接入新功能。
- Logo 移到顶部问候语左侧，旁边显示日期与时间。
- 首页原“进行中的项目”区域升级为“项目总览”。
- 点击项目卡后，工作台原地切换为项目驾驶舱；使用返回按钮回到首页。
- 甘特图以主要阶段为主，点击阶段后展开细项。
- 阶段进度根据“细项清单”复选框自动计算。
- 阶段同时记录计划日期和实际日期。
- 项目总体进度按阶段等权计算。
- 工作台只允许直接勾选阶段细项；其他内容在阶段笔记中维护。
- 当前阶段优先取“进行中”；没有进行中阶段时，取顺序最前的未完成阶段。
- 阶段状态固定为：未开始、进行中、等待、已完成。
- 项目状态固定为：筹备中、进行中、暂停、已完成、已归档。
- 新模板适用于所有未来项目。
- Obsidian 管理项目结构，TickTick 只管理需要提醒的行动，不做项目细项同步。
- 项目财务从 Cashlog 中带项目双链的记录自动汇总。
- 日记中出现项目双链的相关段落自动进入项目“最近记录”。
- 桌面端显示甘特图；iPhone 使用阶段时间列表。

## 3. 工作台信息架构

### 3.1 首页

首页保留日记轮播、今日必完成、今日任务与统计卡。项目区域替换为“项目总览”。

项目总览默认只显示状态为“筹备中”和“进行中”的项目，并支持筛选暂停、已完成和已归档项目。每张项目卡显示：

- 项目名称与总体状态
- 当前阶段
- 总体完成百分比
- 计划完成日期
- 提前、正常或延期状态

项目卡是进入项目驾驶舱的唯一主入口。

### 3.2 项目驾驶舱

桌面端包含：

1. 返回首页按钮与项目名称。
2. 项目状态、总体进度、当前阶段、计划完成日期和进度偏差。
3. 阶段甘特图，支持“本月 / 三个月 / 全项目”。
4. 当前阶段详情，显示细项、材料设备、负责人、等待原因与验收要点。
5. 项目财务汇总与分类入口。
6. 来自每日日记的最近项目记录。

点击甘特条或阶段行时，在驾驶舱内切换当前阶段；点击阶段标题时，在 Obsidian 新标签页打开对应阶段笔记并保留工作台。

### 3.3 移动端

iPhone 不显示横向甘特图，改为按计划日期排列的阶段列表。阶段可展开查看细项并直接勾选；日期、材料、等待原因、验收要点和阶段记录通过打开阶段笔记维护。左侧预留功能栏在移动端隐藏。

## 4. 文件结构

```text
02 项目/
├─ 项目索引.md
└─ <项目名>/
   ├─ <项目名>.md
   ├─ 阶段/
   │  ├─ 01 <阶段名>.md
   │  ├─ 02 <阶段名>.md
   │  └─ …
   └─ 附件/
```

不再为项目维护手写 Mermaid 甘特图、独立 Kanban 文件或 `.components` 项目视图。

## 5. 项目主页数据模型

示例：

```yaml
---
type: 项目
project_id: project-20260902-001
project_status: 进行中
client: ""
address: ""
manager: ""
plan_start: 2026-09-01
plan_end: 2026-12-01
contract_amount: 0
budget: 0
amount_received: 0
members: []
suppliers: []
tags:
  - 项目
---
```

`project_id` 创建后保持不变，用于项目改名后的稳定关联。`suppliers` 保存指向 `04 资源/供应商与品牌` 的双链。项目状态由用户维护，工作台不根据阶段擅自覆盖。

项目主页正文保留项目信息、重要事项与风险、项目成员、供应商和附件入口。自动统计内容在工作台渲染，不写回主页正文。

## 6. 阶段数据模型

示例：

```yaml
---
type: 项目阶段
project_id: project-20260902-001
project: "[[省地勘局宿舍]]"
order: 6
status: 进行中
planned_start: 2026-09-01
planned_end: 2026-09-10
schedule_status: 草案
actual_start: 2026-09-02
actual_end:
owner: ""
depends_on: 05 设备安装
tags:
  - 项目
---
```

正文固定结构：

```markdown
# 06 水电暖改造

## 细项清单

- [ ] 厨房
- [ ] 卫生间

## 材料 / 设备预定

## 等待原因

## 验收要点

## 阶段记录
```

工作台只修改“细项清单”标题下的复选框，不修改其他章节。

## 7. 计算规则

### 7.1 阶段进度

阶段进度为“已勾选细项数 ÷ 细项总数”。无细项时显示“待完善”，不按 0% 参与项目进度计算。

当全部细项从未完成变为完成时：

- `status` 自动设为 `已完成`。
- 若 `actual_end` 为空，写入当天日期。

当已完成阶段出现取消勾选时：

- `status` 自动恢复为 `进行中`。
- `actual_end` 清空。

### 7.2 当前阶段

1. 按 `order` 排序，优先选择第一个 `status: 进行中` 的阶段。
2. 如果没有进行中阶段，选择顺序最前且未完成的阶段。
3. 所有阶段完成时，显示“全部完成”。

### 7.3 项目总体进度

每个有效阶段权重相同。项目总体进度为所有有效阶段进度的算术平均值。没有细项的阶段不参与分母，并在驾驶舱显示“阶段待完善”提示。

### 7.4 进度偏差

- 未完成阶段超过 `planned_end`：显示延期天数。
- 已完成阶段使用 `actual_end - planned_end` 计算提前或延期。
- 缺少计划日期：显示“排期待完善”，不阻断其他阶段渲染。
- `schedule_status: 草案` 的阶段显示“草案排期”，参与甘特图展示，但不计算延期；只有改为 `已确认` 后才计算进度偏差。

## 8. 甘特图

桌面端甘特图以主要阶段为行，计划时间为基础时间条，实际开始与完成以第二层标识叠加。状态颜色分别表示未开始、进行中、等待和已完成，并显示今天标线。

视图范围：

- 本月：默认视图。
- 三个月：当前月前后扩展。
- 全项目：按最早计划开始和最晚计划完成自动缩放。

甘特图只展示阶段，不直接平铺厨房、卫生间和材料预定等细项。

## 9. 新建项目向导

工作台提供“新建项目”按钮。向导分两步：

1. 填写项目名称、客户、地址、负责人、计划日期、合同金额、预算、已收款、成员与供应商。
2. 从标准阶段库中选择阶段。默认勾选 15 个室内施工阶段，可增删并调整顺序。

系统先在内存中生成完整文件清单并校验项目名、路径、项目编号、阶段顺序和文件名。校验通过后再写入项目目录。目标目录已存在时停止创建并提示用户，不覆盖已有项目。

## 10. Cashlog 财务联动

项目财务读取包含项目双链的 Cashlog 行，例如：

```markdown
- #支出/项目/材料 [[省地勘局宿舍]] 灯具定金 💴-860 ➕2026-07-14
```

驾驶舱顶部显示合同金额、累计收入、累计支出和当前余额；下方按 Cashlog 标签分类统计。点击分类后展开对应流水。工作台不修改 Cashlog 内容。

无法解析的账目行被跳过，同时显示“有 N 条项目账目待检查”，不影响其他账目统计。

## 11. 每日日记联动

工作台扫描日记目录，查找包含项目双链的段落。最近记录按日期倒序展示日期、相关段落摘要和原日记入口。点击记录后在新标签页打开对应日记。

不使用智能体生成摘要，不调用 DeepSeek API，也不复制整篇日记。

## 12. 写入安全与错误处理

- 仅通过 Obsidian Vault API 创建和修改文件。
- 修改复选框前重新读取目标文件，避免覆盖其他设备刚同步的内容。
- 只定位“细项清单”章节内的目标复选框。
- 写入后再次读取并核对目标状态；失败时恢复工作台显示并提示用户刷新。
- 文件缺失、字段缺失或日期无效时，局部显示可修复提示，不让整个工作台崩溃。
- Remotely Save 同步期间不缓存旧文件正文作为写入依据。

## 13. 省地勘局宿舍重建规则

实施时直接删除 `02 项目/省地勘局宿舍` 现有内容，不建立备份，不保留 `_旧版参考`。这是用户明确选择的处理方式。

随后按照新模板重建：

- 保留现有 15 个阶段名称和顺序。
- 整理并保留现有阶段细项。
- 整理并保留现有材料与设备提醒。
- 将早期草案日期写入 `planned_start / planned_end`，并标记 `schedule_status: 草案`；清空不可信的实际日期。草案排期不会产生延期警报。
- 状态以现有阶段文件的 frontmatter 为准：`待处理` 转换为 `未开始`，`进行中` 保留为 `进行中`，`等待中` 转换为 `等待`。旧 Components 分组不参与判断，因此当前阶段为“06 水电暖改造”，“09 瓦工”为等待，其余阶段为未开始。
- 删除旧 Mermaid、Kanban、Components 和施工任务总表。

## 14. 验证标准

自动化测试必须覆盖：

- 项目主页与阶段文件解析。
- 复选框范围识别与写回。
- 阶段进度、项目总体进度和当前阶段算法。
- 实际日期自动写入与撤销。
- 提前、延期和缺少排期计算。
- 甘特图三种时间范围。
- Cashlog 项目识别、分类汇总和异常行统计。
- 日记项目段落提取。
- 新建项目向导的校验和文件生成。
- Windows、Mac 与 iPhone 响应式布局。

真机验收必须确认：

- 工作台左侧预留栏在桌面显示、在手机隐藏。
- Logo、日期与时间位于顶部。
- 首页项目总览和项目驾驶舱切换正确。
- 阶段勾选可以可靠写回 Markdown。
- 点击阶段和日记记录会在新标签页打开原文件。
- Remotely Save 同步后 Mac 和 iPhone 能读取同一套数据。

## 15. 不在本期范围

- 不实现 Obsidian 与 TickTick 的项目双向同步。
- 不在工作台直接编辑阶段日期、材料、验收或长文本记录。
- 不使用 DeepSeek 自动生成项目摘要。
- 不引入新的第三方项目管理插件。
- 不恢复旧 Components、手写 Mermaid 或独立看板视图。
